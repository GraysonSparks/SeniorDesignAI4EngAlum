# What every file does

One table per folder. The **Web team** column says what hosting on eng.auburn.edu/giving needs:

- ✅ **Needed**: the live assistant runs it or reads it. Deploy it.
- 🔧 **Upkeep**: not used while answering, but run on the server when content changes.
- 🧪 **Testing**: checks and test pages. Useful after a change, not needed to serve visitors.
- 💻 **Laptop**: only for running the assistant on the Windows demo laptop.

How to host it: [`WEB_TEAM_HANDOFF.md`](WEB_TEAM_HANDOFF.md). How to update the content:
[`CONTENT_REFRESH.md`](CONTENT_REFRESH.md).

## What a live deployment needs, in short

1. A server with an NVIDIA GPU (8 GB or more) running Ollama with `qwen3.5:9b` and `nomic-embed-text`.
2. `rag/`, `content/` and `scraped_pages/` on that server; `pip install -r rag/requirements.txt`;
   `python ingest.py`; `uvicorn app:app --port 8000` behind the proxy.
3. The environment variables in the handoff guide (CORS, proxy, email).
4. One tag on the giving page: `<script src="https://<backend-host>/chat-widget.js" defer></script>`.

## `rag/`: the assistant

| File | What it does | Web team |
|---|---|---|
| `app.py` | The web server. Handles `/chat`, `/contact` (follow-up form), `/unanswered`, `/health`, `/reload-rules`, and serves `chat-widget.js` and the test site. Started with `uvicorn app:app`. | ✅ Needed |
| `rag.py` | The core. Turns a question into a search, finds the closest approved content, asks the model, checks every link against the sources, and adds the staff contact cards. Also holds the fixed replies that skip the model ("Who can I contact?", "Can someone call me?"). | ✅ Needed |
| `config.py` | Every setting and its default (models, paths, contact details, email). Each one can be overridden with an environment variable. | ✅ Needed |
| `content.py` | Reads the content document and the scraped pages and cuts them into chunks. Used by `ingest.py`, and by `rag.py` for the response rules. `python content.py` prints every chunk. | ✅ Needed |
| `routing.py` | Builds the "who do I talk to about Aerospace?" table from the staff directory page each time the server starts. `python routing.py` prints it and warns if a contact went stale. | ✅ Needed |
| `leads.py` | Saves a follow-up form submission (only with consent) to `CONTACT_REQUESTS_FILE`. | ✅ Needed |
| `notify.py` | Emails follow-up requests and unanswered questions to Ed (or whoever `NOTIFY_TO` names). | ✅ Needed |
| `requirements.txt` | Exact Python package versions. | ✅ Needed |
| `ingest.py` | Builds the search index (`chroma_db/`) from the content document and scraped pages. Run once at setup and after every content change, then restart. | 🔧 Upkeep |
| `eval_models.py` | 63 scored test questions against the real model (right facts, right contact, no invented links). All should pass after any change. | 🧪 Testing |
| `test_contact.py` | 18 checks of the follow-up form, consent, spam limits and `/unanswered`. | 🧪 Testing |
| `test_notify.py` | 13 checks of the emails, using a fake mail server. | 🧪 Testing |
| `run_test_prompts.py` | Prints answers to the content document's "Suggested Initial Test Prompts" for reading by eye. | 🧪 Testing |
| `requirements-windows.txt` | Package versions for the Windows laptop. | 💻 Laptop |
| `README.md` | Developer setup and commands. | Reference |
| `chroma_db/` | The search index. Generated by `ingest.py`, not in git. Location set by `CHROMA_DIR`. | ✅ Generated on the server |

## `rag/static/site/`: the widget and the test site

| File | What it does | Web team |
|---|---|---|
| `chat-widget.js` | **The drop-in widget.** One file, no dependencies, styles scoped under `#aug-chat`. The giving page loads it with one script tag. If the backend can't be reached it shows Ed's details (`MAIN_CONTACT` near the top). | ✅ Needed |
| `index.html`, `ways-to-give.html`, `eagle-society.html`, `team.html` | A copy of the giving pages with the widget already added, served at `/` for trying it out. | 🧪 Testing (can be blocked in production) |
| `site.css` | Styles for those test pages only. The widget does not use it. | 🧪 Testing |

## `content/`: the main knowledge source

| File | What it does | Web team |
|---|---|---|
| `AI4EngAlum Giving Content for RAG.odt` / `.docx` | The answers Advancement approved. Each `GIVING-<TOPIC>-01 — <Question>` section has the answer and a `Source:` URL. The "Recommended Response Rules" section sets how the assistant behaves. Either file can be edited; the newer one is used. | ✅ Needed |

## `scraped_pages/`: the official pages, as text

| File | What it does | Web team |
|---|---|---|
| `eng_auburn_edu_admin_development_index_html.txt` | The staff directory. Gives the staff answers and the department/region routing. | ✅ Needed |
| `give_auburn_edu_campaigns_*.txt` | Each department's giving page. | ✅ Needed |
| `_manifest.csv` | Which official URL each file came from; answers cite these links. | ✅ Needed |
| Other `.txt` files, `excluded/` | Other giving pages the scraper saves for reference. Not indexed: their content is already covered by the content document. | Reference |

## `scraper/`

| File | What it does | Web team |
|---|---|---|
| `scrape_giving_pages.py` | Re-downloads the official pages into `scraped_pages/`. Run each semester or when staff change; add a page by adding its URL to `URLS`. Then run `ingest.py`. | 🔧 Upkeep |

## `windows/`: the demo laptop

| File | What it does | Web team |
|---|---|---|
| `Setup.bat` / `setup.ps1` | One-time install: Python, packages, Ollama, models, index, then all checks. | 💻 Laptop |
| `Start.bat` / `start.ps1` | Starts Ollama, loads the models onto the GPU, starts `app.py`, opens the test site. Ctrl+C stops everything. | 💻 Laptop |
| `Stop.bat` / `stop.ps1` | Stops the app, unloads the models, quits Ollama, confirms nothing is left. | 💻 Laptop |
| `Status.bat` / `status.ps1` | Shows whether Ollama and the app are running and where the models are loaded. | 💻 Laptop |
| `common.ps1` | Shared settings for the scripts above, including the environment variables. | 💻 Laptop |
| `README.md` | How to use the scripts. | 💻 Laptop |
